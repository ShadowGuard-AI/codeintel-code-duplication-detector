Duplicated Blocks, Named Plainly

codeintel-code-duplication-detector identifies and reports instances of duplicated code blocks within a codebase to improve maintainability and reduce potential bugs.

The scope stays at README size: files in a codebase that the user points the tool at. No live monitor claim and no running system claim is made here.

Acquisition, One Step Only

git clone https://github.com/ShadowStrikeHQ/codeintel-code-duplication-detector

Shown as one step only, mistaken organisation included. The correction route is the DEFECTS record in the README; this panel does not correct it. No directory change step, no pip install step, and no requirements file is added, because the README mentions none of them.

Invocation

./codeintel-code-duplication-detector [params]

That is the only usage line the README gives. It names no target path argument for the codebase, and the four parameters below contain no target path either. How a codebase reaches the tool is therefore a gap in the README, stated here at the same prominence as the line itself.

Four Markers on the Line

-hShows the help message and exits.
-mGives the minimum number of lines for a code block to be considered a duplicate.
-rGives the path to the report file.
-eGives a list of file or directory names to exclude from the analysis.

Too Short to Count

The minimum lines setting decides which blocks are long enough to count as duplicates. The README gives no default for it.

When a File Cannot Be Read

If any Python file under the target cannot be read, the report still covers the files that were read, the unreadable files are named in the log and in the report, the clean no duplicates line is not printed for that run, and the run exits 1.

Unreadable Means Exit One

All four consequences stand together here, in order, at full size.

Missing from the README: no default for -m, no form for the -e list, no sample report, and no example run, so a reader cannot learn those things from this page.
